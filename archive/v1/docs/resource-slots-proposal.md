## Source and mapping

Engine baseline: HarflowMCP `9b5ab37964b1b6bb17e497c957d42654786f5be8`, `contracts/v1/ctl-phase-slot-held.json`, `ctl-phase-slot-queued.json`, `ctl-phase-slot-refused.json`, `ctl-phase-slot-cleanup-uncertain.json`, `docs/resources-and-worktrees.md` and `docs/contracts.md`. The `phase-slots.v1` status distinguishes configuration, service, leases, events and truncation. Resource holders and queue include legacy task/workflow scopes; task `phase_slots` supplies phase state and actual blockers. Resource names, configured capacity, consuming reservations, owner identity, state and timestamps are fixture representations of those fields. Names come from separately qualified task/run metadata, not from lease identity. Missing names fall back to type and ID; unavailable associations cannot open a detail. Queue positions are explicit fixture values. Only a queued owner's actual holders and earlier same-resource FIFO waiters appear in its blocking disclosure. First in, first out means earlier waiters go first; later waiters are not blockers. Borrowed holds share their parent reservation and do not consume extra capacity. Cleanup pending, running, failed or uncertain remains occupying capacity. `deadline_at` is deliberately omitted from the overview; no ETA is inferred.

Mac baseline: `b2e56aade237ddd96f323b9e0a30e8805405fbd5`, under `macos/HfFeatures/MainWindowFeature/Sources/MainWindowFeature/`: `Sidebar/SidebarListReconciler.swift`, `Sidebar/SidebarNativeRow.swift`, `Coordinator/MainWindowNavigationView.swift`, and `TaskDetail/TaskDetailView.swift`. Local reference exports are style baselines from `7fbed912`, not proof of current whole-window pixels. Browser fonts, materials, controls, status symbols and window chrome approximate native rendering. The Statistics sidebar symbol reuses the exact inline chart path and stroke treatment from `scripts/statistics.js` (`ICONS.chart` and its sidebar entry); it approximates native `chart.bar.xaxis` from `Sidebar/SidebarNativeRow.swift`. The mock detail is a navigation illustration, not evidence that every owner has a task record. No release, repair, configuration or other administrative action is offered.

All fixture names and IDs are synthetic. The fixed example clock is 2026-10-31 14:35: heavy has one holder since 14:32 and two waiters since 14:33 and 14:34; ios-simulator and test-db are unused in the main fixture. Selector mapping:

- `populated` shows the main example; `loading` shows structural placeholders with unknown counts. The external completion buttons resolve loading to `populated`, `empty` or `error`.
- `empty` represents a qualified configured snapshot with no resources; `disabled` represents configuration not enabled; `unsupported` represents an engine without the contract; `error` represents an unreadable snapshot. None claims zero usage for unknown data.
- `refreshing` retains the last qualified fixture snapshot, including its rows, cleanup status, disclosure state, selected detail and scroll position; `refresh-error` retains the same snapshot with an explicit stale label. Snapshot contents (including qualified empty), freshness and cleanup-service availability are tracked separately. Refreshing and refresh failure preserve the current content and service qualifier, including in the task/workflow detail. Holder details use the snapshot cleanup state and explain that its reservation still occupies capacity, rather than repeating the earlier execution status. The cleanup service notice describes the supervisor as not running and does not imply stale counts. Service failure preserves current rows, cleanup state and count qualification; it does not substitute the populated fixture. Selecting a new content fixture resets freshness and service availability. Initial loading, disabled, unsupported and unreadable states have no qualified retained snapshot. These do not restart loading shimmer.
- `cleanup-pending`, `cleanup-running`, `cleanup-failed` and `cleanup-uncertain` retain the consuming holder with its cleanup state. `service-unavailable` represents an unavailable cleanup service with a retained snapshot; it distinguishes that failure from engine unavailability and does not imply every non-hook acquisition fails.
- `long` covers a long title, missing metadata and long IDs; `workflow` covers workflow and whole-task associations; `multi` opens test-db on entry and shows two consuming holders plus a borrowed hold sharing the explicitly named parent reservation; `truncated` labels observed counts as lower bounds and explicitly shows overcommitment without asserting complete counts.

Skeleton highlights are clipped to individual shapes and loop at 1.4 seconds. System Reduce Motion or the specimen override makes them static, an accessibility choice for this proposal that differs from the Statistics opacity pulse. Initial completion uses the separately approved 180 ms ease-out opacity arrival; reduced motion swaps immediately. Refreshes preserve retained rows and do not replay arrival. The persistent loading announcement describes initial loading; skeleton shapes and duplicate queue-position badges are decorative. Blocking disclosures reference a panel only while it is present. Appearance and width changes preserve disclosures; Reset restores fixture defaults.

Browser and native verification remain separate. Inspect actual Light and Dark pixels, widths, keyboard navigation and focus return, reduced motion, refresh behavior and file URL operation before using this as an implementation reference. Native rendering, accessibility, lifecycle and engine integration remain unverified.

The specimen uses a 760-point preferred height so the principal populated groups are visible at 1200 points; the native window minimum remains 1000 × 620 points. Content remains scrollable.
